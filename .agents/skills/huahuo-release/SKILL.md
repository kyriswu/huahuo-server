# 花火 Server 发布

先读仓库 `AGENTS.md`、`docs/runbooks/standard-release.md`；涉及分支、团队权限或发布按钮时再读 `docs/runbooks/team-releases.md`。仓库内的规范与执行器是同一套流程，不复制另一个发布框架。Skill 指导准备与判断，实际强制权限依靠 GitHub 分支规则、环境限制和云身份，不能把文档约定说成已生效的权限。

本发布 Skill 目录及 `.github/CODEOWNERS` 由仓库所有者审核；其他 Skill 不在专属范围内。保护是否生效须核对 GitHub 规则与目标分支的 CODEOWNERS，详见团队手册；本文件自身不能执行权限控制。

## 分支与环境的含义

- `main` 是 Git 分支：当前提供受保护的发布 workflow、调用器、依赖及 Compose 等部署控制文件。下文“从 main 启动 Action”表示执行 main 中的流程，不表示测试业务代码来自 main。
- `test` 是 Git 分支：提供测试服务器实际运行的业务代码和本期发布清单，镜像按选定的 test 提交构建。
- 测试／生产环境是部署目标及各自配置，不是分支名称；正式生产尚未接入，不能从 main 的存在推定生产已部署。

操作示例：GitHub Action 选择 **main** → 运行 main 的 workflow → 校验 **test** 的提交与 CI → 将该 test 版本部署到测试服务器。业务 SHA 与流程控制 SHA 分别记录。

## 先判断，再形成候选

1. 核对当前工作区、目标环境和它**实际成功部署的 SHA**。使用已授权的只读记录；不知道目标或记录过期就说明缺项，不能拿 `origin/main` 冒充线上版本。保护未提交工作，不操作同级 App。
2. 用该 SHA 到候选的累计差异分析影响。除了 SQL 和 ENV，还看业务代码对字段/配置的首次读取、API/事件载荷、队列任务、异步回调、权限、缓存/对象存储格式及外部依赖。只读核对真实 App 契约；只记录与本期有关的证据。
3. 对有实质取舍的变更，给出推荐方案、依据、代价及需要用户决定的点。能通过只读数据规模/锁情况调查、源码和隔离演练确认的，先完成这些工作。不把信息不足写成兼容=true，不因普通低风险实现选择反复索取批准。

本地开发与测试环境当前共用数据库及云资源。先核实迁移记录和仍在运行的测试旧版；本地执行结构变更会立即影响它，不能等换容器才考虑兼容。发布保留迁移阶段：已执行编号和 checksum 一致且没有 pending 时显示“无需执行”，有 pending 按清单执行，差异则停止。CI 始终用独立临时 PG/Redis，不清共享库，不把共享资源变成隔离测试清理对象或调用真实付费服务。

小且可控的数据修正可以随发布迁移；大型或不确定的同步通常独立运行。依据是可触达行数、SQL/索引计划、事务与锁持续时间、并发写入、失败恢复和已有演练，而非统一的行数阈值。支持“双写先上线 → 独立同步 → 对账 → 后续切读 → 后续清理”；这是一种方案，不是所有改字段都必须采用的流程。若需要独立回填，只记录其方案/前置结果，不把作业偷偷接入发布脚本。

## 形成可审查结果

- 修改 `scripts/release/plan.json`：明确基准 SHA、服务、迁移、数据处理方式、配置、依赖、兼容判断与验收级别。它描述当前候选，历次版本由 Git 保存。涉及数据库时填写本期只读 `verify-db.sql`；无变化也明确填写空清单。
- 新 SQL 用 `pnpm db:generate descriptive_name` 起草。已执行 SQL 冻结；不改 checksum、不重新初始化已有库。生成器的草稿标记只有在 SQL 填写、审查后才去掉。每文件一个事务，锁/SQL有预算，必要的普通索引、权限、约束与启动配置一同考虑。不自行添加事务控制或物理外键。
- 配置真实值只由授权环境提供，仓库只放键和说明。新增变量有默认且无需实际值变化时可复用成功配置；代码已停止读取且清单标记 `remove/required:false` 的旧键残留也不要求另做候选 ENV。修改键、删除必需键或新增无默认值的键仍需候选配置。保留 `reviewedFiles` 审查，确认旧读取确已移除，并检查实际 Compose 注入到每个角色的值，不以 `.env.example` 有键代替验证。
- 核对数据库 `deployment.drainTimeoutMs` 与整条发布链路的时间预算。默认 10 分钟、允许 10—60 分钟；首次排空固定预算、早完即退、到期强退。Compose 3630 秒仅保护上限，不覆盖数据库选择。写库前预算不足就拒绝，不静默缩短；旧镜像不一定读取新键，首次升级须单独验证其交接。完整时间边界见 `docs/runbooks/standard-release.md`。
- 对 API/任务/数据格式变化，补能区分旧版与候选行为的契约或交接用例；根据真实风险选择验证，不为每项机械生成重复测试。外部服务检查限已审的有界只读操作；不为验收调用短信、模型、付费云资源或真实用户数据。
- 测试服务器固定部署 `test` 的业务代码和发布清单；受保护 `main` 提供工作流、调用器、依赖及 Compose。分别固定业务 SHA 和控制 SHA，要求 test 同 SHA 的 push CI 成功。main/test 同步走 PR，本地开发使用 test；沿用测试 environment、云身份、固定实例与保存命令。正式生产尚未接入，部署基准为未初始化/null；测试基准继续保留实际成功 SHA，不重置迁移记录。

## 演练与交付

先运行类型/Lint/构建、相关测试和隔离升级演练。`pnpm test:integration` 在临时数据库从计划基准 SQL 执行到候选，再跑业务集成；它不是生产数据分布模拟，也不自动证明旧二进制所有业务兼容。涉及锁、大表、双写/任务载荷等风险时，补对应代表性用例和实际旧版验证。

候选提交后执行 `pnpm release:check`；它要求干净工作区，校验完整提交而非未提交草稿。修复后重跑受影响检查，保留先前失败事实。最终 PR 必须包含：主要功能与改动范围；冲突文件、双方原意及最终解决方式（无冲突明确写无）；上线清单及需人工操作的时点、角色和完成状态；数据库/配置/依赖变化与验证证据、未验边界。不能用提交列表代替这些内容。ENV 清单逐键说明新增/修改/改名/停用、使用容器、是否必填/默认值、目标要求、准备位置和验收方式；无手动项明确写无需手动调整。不粘贴凭据或内部设施标识到公开页面。

配置存在性和应用解析通过不等于值改对。涉及值修改必须声明 `configuration.verifyFile`，指向本期 `scripts/release/changes/<id>/verify-config.mjs`；新增项涉及范围、开关联动或目标限制时也提供。脚本按 `SERVICE_ROLE` 校验实际容器 ENV，退出非零即阻止写库；比较已审的非敏感目标值，检查缺失、类型、范围、改名后的新键和必要联动。秘密只能校验存在/格式或与授权私密来源比对，不能把真实值或可离线猜测的哈希写进仓库；需精确更换的秘密在上线清单中记录私密来源核验结果，不将格式正确声称为值正确。检查脚本仅做本地配置断言，不访问数据库、网络或计费服务，输出不得含配置值。

测试发布默认由 AI／脚本自动执行：准备完整 PR 与上线清单，检查通过且目标/配置齐备后，直接合并到 test，等待该完整 test SHA 的 push CI 成功，再从受保护 main 发起既有 workflow_dispatch 并跟踪终态、独立验收，无需用户逐次点击 Merge 或 Action。调用器不可用时可通过浏览器操作；不能因此跳过检查、改权限或重复触发。PR 合并锁定已审 head SHA，发布前重新核对 main/test 未移动；已有调用未终态时先查状态，不重发。

main 的合并与正式生产发布仍由用户操作／批准。发布 Skill 或 CODEOWNERS 的修改仍须 owner 审核；已由 owner 在 main 审核合入、内容完全一致的 main→test 同步可自动执行，不重复索取相同内容的批准。纯文档/审核归属变更无需重建并发布业务容器；依据实际文件影响判断，不能把业务/配置改动伪装成文档跳过部署。本地开发保持干净 test。

自动化只使用已授权测试实例、现有身份与固定入口，不自动新建付费资源、编造认证凭据或重置数据库。main 流程或 production environment 的存在不代表生产已部署。

触发后，固定工作流与宿主入口顺序执行；线上不调用 AI 临时生成 SQL/脚本。准备 PR 不代表获得任意环境的部署权限，使用会话已有授权，不额外扩大目标。当前会话已授权的具体动作无需重复确认。

发布失败先辨认“未写库 / 部分迁移已提交 / 已换部分容器 / 已切流 / 已成功但报告失败”。查现有调用和宿主记录，不把本地超时当作远端没执行，不盲目重复触发。应用恢复保留已提交迁移，回退旧应用不能执行旧迁移器。恢复建议必须核对实际状态和可回退范围。

进度按五阶段呈现：预检（含构建、配置）、迁移、迁移验收、容器切换退出、冒烟清理。失败显示已完成 N/5、当前失败阶段和未执行项；只有终态证据时只能报告终态复核，不能补造五步完成记录。

报告分别列出本地替身、隔离真实依赖、实际目标发布结果及未验项目；不把健康通过冒充认证业务通过，不用一次成功承诺 99.99%。应用排空超时使用退出码 124；核实预算到期，不能把提前失败算作正常超时。`forcedRetirements` 与 `OK_WITH_FORCED_DRAIN` 必须明确报告为发生强制退出，不能说旧工作都自然完成。候选脚本、宿主安装与实际部署分别记录，不能凭本地改动宣称已上线。自动化承担可重复执行和阻断，判断、证据和评审仍属于发布准备。
