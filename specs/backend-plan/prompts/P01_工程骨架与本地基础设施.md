# P01 · 工程骨架与本地基础设施

前置阶段：无。

## 本阶段固定部署与 App 参照

- App只读参考仓库：**https://github.com/kyriswu/huahuo-app**。本机后端根为 `huahuo-server`，App位于同级 `../huahuo-app` 且只读；禁止把服务写进App、复制Flutter作为运行依赖或擅自修改UI。
- 同一根目录Compose：`api-server`、`worker`、`admin`、`scheduler`独立容器；`postgres`（可切云）、`redis`、一次性`migrate`。本阶段涉及：api-server、admin、worker、scheduler、migrate、postgres、redis的独立骨架。
- 先按 `07_App代码持续参照与契约核对.md` 核对本阶段：网络客户端、API envelope、错误、Base URL与鉴权注入。路径/符号从当前checkout发现，不猜它们一定在旧目录；记录实际commit和本地改动。
- 实施前保存App基线；过程中每个客户端端点均能追到请求与响应解析；结束更新 `docs/app-reference.md` 和契约测试。不能等P15才第一次对照App。
- 读取不到源码时写UNVERIFIED_APP和受影响API，继续可独立开发部分，不声称兼容、不借此重做前端。
- 同一镜像不等于同一容器。api-server不执行worker任务、不注册admin路由；admin不绕过领域服务直接改支付状态；scheduler只投递/扫描。

## 本机工作区约束（v3，全部阶段适用）

- 优先读取 `../huahuo-app` 的当前本地源码和未提交内容，源地址仅用于识别： https://github.com/kyriswu/huahuo-app 。不要默认clone/fetch/pull或新建参考目录；阶段内记录实际阅读文件的哈希。
- 所有实现、文档、依赖和测试都放现有 `huahuo-server`。不是Code父目录，不是App，也不是再新建huahuo-backend。开始先检查隐藏文件，保留已有工作与数据。
- 同一份 `huahuo-server/compose.yaml` 管理独立容器；只操作本项目资源，保留数据卷，不能全局清理或停止其他项目。
- 按 `11_本机双目录与Docker开工规范.md` 检查本机Docker，必要时启动已安装的本机Desktop；若权限受限申请最小权限，不把ChatGPT的沙箱执行当用户Mac执行。

## 执行方式

先读取 `specs/backend-plan/01_项目总提示词.md`、`02_架构与配置约定.md`、`docs/progress.md`（P01尚不存在则新建），遵守当前工作区AGENTS及11规范。不重建已完成阶段，不以本文建议覆盖已核实的客户端契约。

本阶段要实际写代码、migration/schema、测试和可运行命令，不只写方案。依赖的真实provider未配置时完成接口与明确模拟测试并标阻塞，继续其他可实现部分；生产严禁模拟成功。

阶段结束：运行类型/lint/相关测试，更新progress/provider-status/contract-compatibility/app-reference/container-status，报告实际命令、结果、未验证项。别擅自push、上线、发真短信、真支付/退款、付费任务或改App UI。

## 本阶段交付目标

在独立后端工作区启动一个Compose中的api-server、admin、worker、scheduler、postgres、redis与一次性migrate。HTTP与后台角色真实独立，先交付可测骨架，不再做一轮全量分析。

## 实施要求

1. 从Code或Server正确定位现有huahuo-server及同级huahuo-app，检查隐藏文件/上级Git归属；只在Server增量初始化。按11规范检查本机Docker context、daemon、端口及资源，必要时启动用户已安装的本机Docker，不能重装或清空。读适用AGENTS；不要另建后端目录。初始化TypeScript strict/ESM、Node24 LTS、pnpm、Fastify5、pg、稳定Drizzle与Vitest。核对版本后锁定；不要为了教程方便用RC或多个重复ORM。
2. 建buildApiServer/buildAdminServer两个Fastify工厂及api-server/worker/admin/scheduler/migrate入口。配置按角色校验，Pino带service/instanceId并脱敏，HTTP有requestId/schema/OpenAPI。worker/scheduler各自有健康端点和优雅退出；P01只连接与生命周期骨架，不假称已处理业务。admin先实现私网受限入口/健康，敏感路径默认拒绝，P02接独立登录。
3. 根目录唯一compose.yaml落实06规范和examples蓝图：api-server/worker/admin/scheduler是四个服务，postgres/redis分别容器，migrate是一次性容器。PG通过local-db profile启动，云PG不依赖被禁用的postgres。migrate对实际PG有限重试，成功后常驻服务启动；Redis健康依赖与运行时重连分开。锁定完整镜像tag/digest，不固定container_name。
4. 配置每角色DB连接/连接池、TLS/CA、迁移专用URL、两个Redis URL、独立api/admin端口、APP_ENV与mock守卫。输出.env.compose.local.example、.env.compose.cloud.example与可选宿主调试例子。本地凭据随机生成、仅开发seed，常驻服务不使用PG初始化superuser；migrate credentials不传其他角色。Redis AOF/noeviction/内存预算。
5. migrations命令、独立测试库、开发seed框架；迁移不在所有进程启动时自动执行。实现/health/live与/health/ready，分别表达进程可用和依赖就绪，不泄露连接串。
6. 实现pnpm app:reference及app:reference:diff，App地址固定在07规范；参考默认为同级../huahuo-app；GitHub只作来源，默认不联网/clone。只读记录commit/工作树或NO_GIT/已读文件哈希/本阶段源码证据。只核对网络客户端与基础解析；不做全仓重审。配置本地路径不成为Compose或Dockerfile依赖。
7. 实现start/dev四角色、compose:validate/up/down、db:migrate、test:container-isolation及build/test脚本；Dockerfile多阶段、非root、每容器一个角色，不用concurrently/PM2一容器跑全家。合并AGENTS并生成进度/App参照/容器状态。examples是蓝图，本阶段必须补齐其中引用的真实entrypoint和healthcheck，不能只复制模板就说能运行。

## 必须验证

- pnpm typecheck、lint、build和Fastify inject测试实际执行。
- 真实PG执行SELECT 1与至少一次可重复migration；Redis读写带过期测试key。
- 参数错误返回约定4xx且不泄露secret；health不要求模型/商户凭据。
- 分别启动/停止api-server/admin/worker/scheduler；其中一个停止不杀其他进程；worker骨架与scheduler骨架不运行同一个消费者；测试mock与production配置组合被拒绝。
- api-server返回/admin和/admin/api/v1为404，admin不注册/api/v1的用户业务路由；admin未配置认证前无业务数据公开。
- docker compose config校验本地与云PG模式；云模式完全不含强制postgres依赖。实际compose up/ps检查独立容器和migrate退出0，再验证角色健康、端口和volume。Docker不可执行时如实记阻塞。
- Docker镜像不含Flutter目录、App源文件、.git、.env与开发参考checkout；后端本地App路径不存在时构建仍能成功。

## 不做或不得误报

不要只建目录/README；也不要提前创建全部业务空接口。

## v3 本机必须补齐的验收

- 不依赖App联网可读：从本机记录Base URL/请求封装/解析消费者；App未修改，相关文件阶段前后哈希相符，用户并行修改则明确记录而不还原。
- 正确识别从Code与从Server启动；拒绝Server/App同路径或错误嵌套；Server不空时保护原内容。
- 分开记录本机Docker安装、context本地性、daemon可达、Compose配置通过、镜像构建、容器Up、健康与实际依赖，不能以第一项代替后面全部。
- Node/pnpm缺失时可使用examples/Dockerfile的tooling target完成后端构建工具环境，不需要把App挂进容器，不自动安装全局工具或强制amd64。
- 新环境project默认huahuo-server-dev；已有本项目名/卷/密码保留。同机其他项目不停止、不删除；端口冲突只改本项目配置。
- 输出docs/local-environment.md和docs/runbooks/local-development.md；完整方案见12，P01只验证本机HTTP和容器内部链路，App真机/供应商连通在授权后的P15。
