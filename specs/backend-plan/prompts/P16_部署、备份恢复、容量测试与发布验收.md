# P16 · 部署、备份恢复、容量测试与发布验收

持续约束：执行前阅读 [知识图谱标签化补充要求](../13_知识图谱标签化补充要求.md)；图谱只做标签驱动的素材关联，后续也不得自行增加向量/RAG/Dify 知识库。与旧条款冲突时以该补充要求为准。

前置阶段：P01—P15。

## 本阶段固定部署与 App 参照

- App只读参考仓库：**https://github.com/kyriswu/huahuo-app**。本机后端根为 `huahuo-server`，App位于同级 `../huahuo-app` 且只读；禁止把服务写进App、复制Flutter作为运行依赖或擅自修改UI。
- 同一根目录Compose：`api-server`、`worker`、`admin`、`scheduler`独立容器；`postgres`（可切云）、`redis`、一次性`migrate`。本阶段涉及：全部独立服务、一次性migrate、本地/云PG、备份恢复及发布验证。
- 先按 `07_App代码持续参照与契约核对.md` 核对本阶段：Base URL/TLS、SSE、上传、最终兼容矩阵与此前阶段基线变更。路径/符号从当前checkout发现，不猜它们一定在旧目录；记录实际commit和本地改动。
- 实施前保存App基线；过程中每个客户端端点均能追到请求与响应解析；结束更新 `docs/app-reference.md` 和契约测试。不能等P15才第一次对照App。
- 读取不到源码时写UNVERIFIED_APP和受影响API，继续可独立开发部分，不声称兼容、不借此重做前端。
- 同一镜像不等于同一容器。api-server不执行worker任务、不注册admin路由；admin不绕过领域服务直接改支付状态；scheduler只投递/扫描。

## 本机工作区约束（v3，全部阶段适用）

- 优先读取 `../huahuo-app` 的当前本地源码和未提交内容，源地址仅用于识别： https://github.com/kyriswu/huahuo-app 。不要默认clone/fetch/pull或新建参考目录；阶段内记录实际阅读文件的哈希。
- 所有实现、文档、依赖和测试都放现有 `huahuo-server`。不是Code父目录，不是App，也不是再新建huahuo-backend。开始先检查隐藏文件，保留已有工作与数据。
- 同一份 `huahuo-server/compose.yaml` 管理独立容器；只操作本项目资源，保留数据卷，不能全局清理或停止其他项目。
- 按 `11_本机双目录与Docker开工规范.md` 检查本机Docker，必要时启动已安装的本机Desktop；若权限受限申请最小权限，不把ChatGPT的沙箱执行当用户Mac执行。

## 执行方式

先读取 `specs/backend-plan/01_项目总提示词.md`、`02_架构与配置约定.md`、`docs/progress.md`（P01尚不存在则新建），遵守当前工作区AGENTS及11规范。不重建已完成阶段，不以本文建议覆盖已核实的客户端契约。

本阶段要实际写代码、migration/schema、测试和可运行命令，不只写方案。依赖的真实provider未配置时完成接口与明确模拟测试并标阻塞，继续其他可实现部分；生产严禁模拟成功。

阶段结束：运行类型/lint/相关测试，更新progress/provider-status/contract-compatibility/app-reference/container-status，报告实际命令、结果、未验证项。别擅自push、上线、发真短信、真支付/退款、付费任务或改App UI。

## 本阶段交付目标

形成可交付运维的构建、迁移、部署和恢复流程，证明已实现的范围，不擅自上线。

## 实施要求

1. 多阶段Dockerfile、非root运行、api-server/worker/admin/scheduler独立容器及命令、一次性migrate、只读根文件系统与必要tmp/存储卷、按角色CPU/内存/连接池预算。镜像复用但PID/健康/退出/配置分离，禁止单容器多角色、固定container_name和Docker socket挂载。
2. 同一根compose.yaml同时定义全部角色，本地PG profile和云endpoint配置切换；admin仅私网/回环，Postgres/Redis不映射公网；可信反向代理/TLS、SSE不缓冲与合理timeout，App/Dify工具受保护HTTP入口配置。
3. PG迁移release job、现存数据升级、expand/contract策略与应用回退手册。破坏性down migration不能自动执行；事务外索引创建等操作按实际migration工具支持验证。
4. PG与文件存储备份、加密/保留、恢复到独立测试环境并校验资源引用/账本/任务。Redis恢复不是唯一手段，验证PG任务对账；云endpoint迁移不只是改URL。
5. 对10万篇级别用户与多租户实际分布、CRUD/搜索、SSE连接、任务队列、商业交易并发进行分层压测。报告硬件/数据/版本/索引/并发/P95/QPS/费用，不承诺无限并发。
6. 故障注入按总验收清单，特别是Redis不可用、worker被杀、provider提交未知、重复回调、资料删除、超额并发。
7. 发布前配置校验：生产模拟provider拒绝、商户与环境隔离、token/证书、套餐政策、成本上限、能力开关、审计/告警、数据删除政策、来源授权。
8. 输出release checklist、runbooks、最终scope/provider/contract矩阵和未完成项。正式云资源创建、生产migration、支付/退款测试和发布均需用户授权，不替用户默默操作。

## 必须验证

- 从干净目录按README启动并复现测试；build+verify实际执行，有阻塞就记录。
- 四角色分别重启后任务/结果可恢复，admin宕机不影响API；worker可扩副本，scheduler重复实例有PG防重，迁移受锁且不由常驻服务自启动。
- 新版本明确执行一次migrate并检查目标schema，不能用之前退出0的旧容器充数；失败退出非0，不放行不兼容应用。
- 本地/云PG的同Compose config与实际启动证据分别记录；云服务无授权时不冒充真实云验证。
- 从备份恢复并验证至少资产/文件引用/余额/订单/数字孪生数据，不只证明备份文件存在。
- 接口、用量、延迟SLO有实际测试结果；真实未接入功能在capabilities中关闭。
- 最终报告明确：交付的是独立后端、独立管理API与最小运营网页、worker/scheduler和Compose；不含重做App UI、真实蓝牙硬件认证或商店审核完成。

## 不做或不得误报

这是发布准备，不是获得自动生产部署/真实交易授权。

## v3 本机验收不等于生产发布

记录Mac架构、Docker分配资源、上下文和本项目资源归属；不得以本机“全容器健康”宣称云端/商店已经上线。APP_LOCAL_PATH只用于开发参照，不进入交付镜像或运行环境；在没有../huahuo-app的受控CI上下文仍应能构建后端。不可为验证独立性而重命名/移动用户App目录。真实PG备份恢复使用新隔离环境，不能破坏当前开发卷。
