# 全项目验收与发布门槛

“代码写完”“本地模拟通过”“真实沙箱通过”“生产已启用”必须分开统计。不要用测试替身覆盖整条外部调用，再标记真实支付或转写完成。

## 1. 每阶段共同门槛

- 代码、迁移、schema、OpenAPI和测试对应；没有只返回200/空数组的占位API冒充业务完成。
- 至少2个用户、2个工作区的授权隔离和交叉引用测试。
- 所有变更通过typecheck/lint/相关单元测试；真实PG/Redis测试记录已运行或阻塞。
- 新旧migration路径均可用；测试使用隔离库，不能误执行生产重置。
- 金额、额度、ID、时间、游标、ETag及幂等语义一致；未知状态不默认为成功。
- 文档注明真实配置、缺失provider、所需手动商户/云控制台步骤。

## 2. 必须打通的业务验收链

### E2E-A：身份和资产
短信/测试登录 → 工作区 → 写一篇原文 → 追加资料 → 标签生成或人工标签 → 搜索/图谱读取 → 内容详情。保存原文不依赖标签生成成功；用户B不可查看、搜索或下载用户A的任何引用资源。

### E2E-B：录音卡素材
受控设备归属 → 提供手机已同步的音频资源 → 上传核验 → ASR → 说话人归属 → 正文/概要 → 内容引用。云集成测试不声称已经测试真实蓝牙/Wi-Fi/设备固件。概要失败不重新提交已完成的ASR。

### E2E-C：会话和创作
会话带文件/图片等合法附件 → Dify/模拟provider运行 → SSE中断 → 重连 → 读取唯一结果 → 再打开历史继续聊天。重开的上下文既能显示附件，也要根据供应商能力取得可使用的原文件/转换内容；显示图片不等于模型已读取。

### E2E-D：数字孪生
本人来源 → 三维度候选 → 确认新增 → 对已有条目建议更新 → 用户先手改 → 旧候选确认冲突 → 重新比较 → 正式内容被授权创作读取。未确认/被删除/来源待复核条目不通过默认工具返回；删除不自动删除原录音，也不能被重试静默恢复。

### E2E-E：商业化
服务器商品与政策 → 下单 → 验证事件 → 支付事实 → 权益 → 额度授予 → Run预留 → 消耗结算。重复事件不双发；退款、续期、取消续订和恢复购买均有明确业务结果。测试沙箱与生产绝不串数据。

### E2E-F：外部世界
已授权source/RSS或测试feed → 拉取去重 → 栏目/文章 → 关注 → 保存个人副本 → 进入创作。源文只读、副本可管理、文章来源保留；不获取付费墙或认证绕过内容。

### E2E-G：运营和隐私
运维查任务 → 只重试允许阶段 → 不越过额度和幂等 → 审计记录；用户导出/注销请求 → 会话撤销 → 后台清理 → 结果核验。备份和法定/业务保留项按明确政策处理，不承诺立即从所有备份物理抹除。

## 3. 故障注入清单

1. API写PG前/提交后/投递前被杀进程：不出现幽灵成功，不丢已受理任务。
2. outbox投递成功但ACK写PG失败：重复投递不重复生成内容或收费。
3. Redis临时断连、内存拒绝写入、重启、测试环境清空队列：PG对账恢复；外部已提交任务不盲重跑。
4. Worker在外部调用前、返回后、结果提交前退出：状态可解释，unknown可查证。
5. 同一用户并发提交超余额或超存储请求：预留正确，不超扣，不通过Redis锁失效穿透。
6. 相同幂等键不同正文、同body重复点击、不同key但同一渠道交易：分别冲突/重放/交易唯一去重。
7. Dify断流、重复终态、取消后迟到结果、计量缺失：不能静默重复付费，不随意释放仍可能发生费用的预留。
8. 文件URL过期、删除后缓存仍存在、跨用户resourceId、伪造Content-Type、超限压缩包、SSRF重定向：拒绝或明确降级。
9. 支付通知验签失败、合法重复、乱序、金额/币种/商品不匹配、商户/应用不匹配：不错误发放权益。
10. 旧来源版本的标签/孪生任务完成时用户已更新：丢弃过期写入或进入待复核，不覆盖用户新结果。
11. 定时job重复触发、漏掉执行窗口、服务重启：对账而不是直接累加时长/额度。
12. 关闭数字孪生使用或撤销权限后旧context缓存命中：下一次外部调用重核权限；已发送的历史输出不冒充能自动撤回。

## 4. 性能验收方法

不宣称框架保证多少并发。准备分层测试：API CRUD/分页、用户10万篇文本的有索引搜索、Worker任务吞吐、真实/模拟Dify延迟、独立SSE连接、商业锁竞争。

逐级增压并记录机器CPU/内存/磁盘、数据库连接池、索引、数据量、用户分布、并发、QPS、P50/P95/P99、错误率、队列等待、provider调用费用。先给可调整SLO，再测达标容量，不以单次本机跑分承诺线上容量。

标签最多5个时单篇的标签共现组合有界；索引随新增/更新增量维护，不每次查询全量文章两两关联。筛选分页使用有界limit与稳定cursor，时间基准明确。不给Agent任意SQL权限。

## 5. 生产启用前

- 明确短信、ASR、Dify、存储、支付、推送的真实启用范围及账号。
- 各渠道 sandbox 已验证，真正的生产测试由用户授权安排。不存在“缺凭证但默认模拟成功”的后门。
- 证书/密钥、TLS、内网数据库、RedisACL/网络、备份加密、脱敏日志有记录。
- 业务数据库/对象存储备份与恢复演练通过；切云endpoint从独立库验证，不直接指向生产运行migration。
- 迁移与应用版本兼容；重大发布使用先扩展再收缩的策略，不删除尚被运行版本使用的列。
- api-server、worker、admin、scheduler的独立容器、健康、就绪、优雅退出、重启行为清楚；migrate一次性作业。
- 关键告警：队列积压、outbox延迟、外部失败率、未知支付/运行、权益授予失败、数据库池耗尽、磁盘/Redis内存、成本异常。
- App关键消费契约用当前源码夹具验证；真实Flutter UI/硬件真机不在后端自动测试中假定通过。


## 6. 继承v2：必须通过的容器与独立仓库验收

- 单个compose.yaml包含api-server/worker/admin/scheduler/postgres/redis/migrate；至少前三者完全独立容器，不是同容器多进程。
- App只读参照 `https://github.com/kyriswu/huahuo-app`，每阶段都有App commit＋真实消费者＋契约fixture；后端运行和镜像不依赖App checkout。
- api-server不装载管理路由；admin独立Session/RBAC，用户JWT不可复用；未授权/admin/api/v1被拒，正常用户服务地址上的该路径为404。
- 停worker不会停API/admin；停止API已入队任务仍执行，admin可查询；停scheduler不丢PG outbox；停admin不影响任务与用户API。
- 不挂Docker socket、不用host网络绕过隔离，不公开数据库/Redis/worker/scheduler；admin默认回环/私网，远程浏览走授权网络/TLS。
- worker扩2副本无需增加宿主端口，不重复扣费/落结果；scheduler只一个默认副本，误启动2个仍有PG租约/窗口去重。
- admin网页可查询真实任务并提交受控重试，worker执行后显示结果和审计；不是空壳页或Swagger伪装管理台。
- 本地PG和云PG用同一Compose。未启动local-db时没有强制postgres depends_on；migrate失败不放行不兼容schema。
- 文件卷由api-server/worker共享；容器重建文件仍在，admin默认不挂私有文件卷。对象存储driver逐项记录真实验证。
- 环境、配置、日志和DB连接池按角色分离，迁移凭据不传常驻服务；镜像不含App源码/.env/.git；同一镜像复用不等于数据权限相同。

## 7. v3本机必须通过

- 后端全部文件在huahuo-server；App默认同级../huahuo-app只读，不自动clone/pull或更改任何App文件。
- 本地App真实读取与相关文件哈希/HEAD/dirty可核对，无Git也能记录源码依据；远端不可达不被当成本机不可读。
- Codex记录真实pwd、Server是否有已有文件、Docker安装/context/daemon/Compose状态；没有把截图当真实终端验证。
- 只操作本项目Compose资源，其他容器/卷无变动；已有.env、密钥和卷不覆盖。端口冲突不kill其他程序。
- Mac架构匹配精确容器镜像，不强制模拟amd64。Docker在用户Mac上的运行证据与本包静态辅助脚本测试分开。
- 容器构建/CI无App源码依赖，Server单仓可部署；绝对宿主App路径不进入镜像、环境变量或对外URL。
- 本机API健康、App真实解析、真机硬件、模型/支付沙箱分别验收；默认不自动开放公网或执行付费调用。
