# 业务模块与阶段映射

这是独立后端的逻辑职责，不是20个微服务。固定运行角色是同一Compose中的api-server、worker、admin、scheduler，另有postgres、redis和一次性migrate。UI入口只是消费视图，不能一页一个数据库系统。

每阶段只读参照App： https://github.com/kyriswu/huahuo-app ，详见07规范。

来源范围来自已提供的移动端说明A—I与后续对话确认；其中录音卡唯一日常来源、数字孪生名称/轻量维护、语义检索后置属于后期覆盖决定。模块目录、数据划分和阶段顺序是本次实施建议。

## 节点验收

- P01—P04：可运行、能鉴权、任务可靠、成本有控制，不接真付费任务前先建立边界。
- P05—P08：文件与素材、转写、聊天/工作流形成可追溯链路。
- P09—P11：创作、数字孪生、外部世界形成产品价值链。
- P12—P14：付款到权益到用量、用户支持、内部运维可用。
- P15—P16：App契约、真实供应商、故障恢复与发布验证，不能拿mock验收代替。

这不是日历工期承诺。实际时间取决于现有App契约复杂度、商户开通、ASR/设备协议、Dify工作流配置和真实联调。付费渠道凭证、文件存储、语音供应商可以并行准备，不等到代码最后才申请。

## 暂不进入的建设

pgvector/Embedding/Rerank、GraphRAG、模型训练、重型数字孪生维护系统、公开社区/团队/课程商城、代表作专属章节、桌面适配、全App UI重构、Kubernetes和多服务治理。

原生声纹/聊天语音输入与“日常音频只能来自录音卡”分开核查；旧代码有入口不表示本期要新增整个手机录音产品。

## v3 当前工作位置与执行方式

上述全部阶段在同机 `huahuo-server` 实施，App默认只读 `../huahuo-app`，源地址 https://github.com/kyriswu/huahuo-app 。不需要默认clone。P01先按11规范做短目录/Docker预检并直接交代码；P15按12规范联调。新环境一份Compose，不修改已有业务范围，不因移动代码目录而重做App。
