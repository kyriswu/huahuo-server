# admin独立容器：范围、权限与最小运营页

用户要求admin、worker、api-server分别容器。本包把admin定义为**独立的管理API及最小运营网页**，以此作为首版默认，不再只交CLI。这不改变App UI，也不是重新选一套庞大后台前端栈。
App产品事实仍参照 https://github.com/kyriswu/huahuo-app ，但App仓库不需要存在运营管理页面才允许建设内部后台。

## 1. 范围与实施顺序

P01：独立admin Fastify实例、容器、内部配置、健康及安全默认拒绝；没有初始管理员不得开放“临时免登录管理”。
P02：管理员身份、密码哈希、Session、RBAC、CSRF、bootstrap/撤销工具；不沿用普通App用户JWT。
P03—P13：业务域提供受控查询/操作服务和必要管理路由；没有页面时不伪称UI完成。
P14：轻量服务端渲染运营页连通这些能力，提供浏览器端验收。
P15/P16：容器隔离、网络、敏感访问和真实provider测试。

默认采用Fastify＋自动转义模板/静态CSS，JS仅作确认和状态刷新。具体模板库由P14选择一个稳定维护的兼容包并锁定；不同时塞多个UI框架。UI路由`/admin`，API`/admin/api/v1`，均只在admin入口装载。

## 2. 需要的页面

| 页面 | 首版内容 | 写操作边界 |
|---|---|---|
| 登录与退出 | 独立管理员身份/错误提示/过期跳转 | 无公开注册、无默认管理员密码 |
| 运行总览 | 队列积压、outbox滞后、失败、未知任务与费用概览 | 数据不足显示未覆盖，不伪造KPI |
| 用户与资源 | 用户状态、工作区、存储/ASR/AI用量 | 封禁/解除须权限、原因和审计；不默认读取全文 |
| 任务与运行 | task/run/attempt/provider identity、事件、错误阶段 | 只对安全阶段retry/cancel/reconcile，走领域服务 |
| 订单与会员 | 订单事实、交易、权益来源和退款状态 | 不直接改paid或isVip；真实退款需授权与确认 |
| 额度流水 | reservation、measurement、ledger与冲正 | 补发/冲正有来源、权限、原因、幂等，不改旧账 |
| 设备与文件 | 归属、resource、上传/ASR状态等元信息 | 无任意SN抢绑定，文件预览额外核权 |
| 外部来源 | source、栏目、频率、启停、最近采集 | URL安全校验，重抓取走worker，不突破授权范围 |
| 工作流配置 | profileId与Dify映射、能力启停、版本 | secret仅引用/掩码，不能编辑任意脚本或SQL |
| 反馈与诊断 | 工单、已脱敏诊断、关联任务 | 敏感附件单独权限，不扩展客服聊天系统 |
| 审计 | 操作者、目标、理由、动作与结果 | 普通管理员无删除审计能力 |

仅是内部运营页面，不增加Flutter导航、不新增公开社区/团队/商城。

## 3. 与用户数据的安全边界

只读运营、任务操作、商业操作、配置管理员等权限分开。请求不能传`isAdmin=true`或借body.userId获得授权。admin的会话密钥、cookie域/path和audience与App分离；登录限流、会话撤销、敏感操作二次确认、CSRF和XSS测试不能省略。

默认只显示必要元信息。打开用户转写、数字孪生正文或附件需明确工单用途/权限和审计，不把其全量复制到普通日志。admin不用直接挂用户文件卷；预览通过相同域权限服务取得受限短期资源。

不提供通用SQL、Shell、Docker socket、Redis FLUSHDB或任意数据库行编辑器。BullMQ可视化组件如选用也必须鉴权且不绕过PG任务状态机，不能把它当完整后台。

## 4. 操作链路

```text
管理员浏览器
  → admin Session / RBAC / CSRF / 请求schema
  → 相同领域服务检查状态、权限、幂等、费用
  → PG写入操作记录＋task＋outbox
  → scheduler投递 → worker执行
  → admin查询稳定taskId/结果 → 写审计并显示
```

原先的api-server与admin在同一Fastify实例的方式不再采用。独立并不意味着admin应直接绕过业务服务操作表；优先共用领域代码，保证API/worker/admin看到同一账本和正式状态。

前端页面刷新不是调度器，管理员关掉网页任务仍可继续；worker停机时显示queued而不是操作成功。API-server暂不可用时admin仍能查PG与受理管理动作，不能依赖公开端内部免鉴权接口。

## 5. 配置与验收

开发默认回环3001，api-server回环3000；远程访问必须显式设地址、TLS与防护。反向代理配置不得把admin错误代理到公开API同一路由。

验收：真实登录→按trace/task查失败→受控retry→worker完成→看审计；普通用户token被拒、CSRF被拒、内容不可注入脚本、旧会话撤销有效、每个高风险动作有来源记录。具体运行证据由Codex产生，本包不声称管理台已经实现。
