## 固定实现

Fastify、PostgreSQL 容器（可配置云PG）、本地 Redis 容器；延续 Node.js24 LTS、TypeScript strict/ESM、pnpm、pg/稳定Drizzle、BullMQ、JSON Schema/OpenAPI 的默认工程方案。锁定实际兼容稳定版本。

`huahuo-server/compose.yaml` 为唯一主拓扑：
- api-server：App API／流／上传下载／受控工具／回调。
- admin：独立 Fastify 管理 API 与最小运营网页。
- worker：独立后台执行。
- scheduler：独立调度、Outbox 与补偿扫描。
- postgres、redis：基础设施各自容器。
- migrate：一次性迁移，成功退出；不是常驻服务。

前三者必须独立容器；允许共用镜像和业务代码。不能在一个容器用 PM2/supervisor/concurrently 混跑。构建 context 是 huahuo-server 自己，不能是 Code 或 `..`；App 不打包、不挂载到业务容器，也不是运行依赖。

## 用户已授权的本机 Docker 工作

用户说明已安装 Docker，并允许必要时启动。你应在**本机 Codex 环境**检查 `docker --version`、`docker compose version`、Docker context 及实际 daemon 是否可达。

- 只操作确认属于本机的 context；远程 context、DOCKER_HOST 指向远端、或沙箱 socket 拒绝时，申请所需最小权限，不切远端、不关闭沙箱。
- 本地 daemon 未运行时，可尝试 `docker desktop start --timeout 120`（先确认 CLI 支持）。macOS 上已安装 Docker Desktop 而无该命令时，可使用 `open -a Docker`，有限等待并再次检查 `docker info`。
- 系统权限/条款弹窗由用户操作；不重新安装另一套 Docker、Colima 或 Kubernetes，不停止整机已有容器。
- 检查现有同名 Compose 资源与 3000/3001 端口。新项目默认 `COMPOSE_PROJECT_NAME=huahuo-server-dev`；发现冲突选择未占用配置或说明，不杀其他服务。
- 允许创建本项目本地开发容器、镜像、命名卷、开发数据库及随机本地密钥并运行测试。不得操作未知旧卷；不得 `docker system prune`、`volume prune`、`down -v`、恢复出厂设置、停止整机 Docker 或执行生产迁移。
