## 改动与执行边界

仓库新增小型Python标准库策略文件`scripts/release/deployment-policy.py`，校验提交顺序、成功状态未变化、角色选择及运行镜像/ENV；不执行部署、写库、改配置或调用云接口。`src/release/plan.ts`检查角色清单与配置使用方一致，保留准确基准、冻结迁移和既有分支/CI校验。策略/校验工具的控制代码同步列入已知白名单，单独更新它们不会自动部署业务；与业务改动一起出现仍须发布清单。

实际宿主原本已有发布锁、清单baseRevision匹配、准确test头检查、同SHA镜像及健康校验。本次复用它们，补齐祖先关系、写库/换容器前成功记录复核、同版本实际ENV核对；不创建第二套执行入口。正式生产尚未接入，本次只操作已确认的测试机Server执行器，不操作Agent或其他实例。

`services`现在控制实际替换的角色。未选角色使用原成功服务定义、镜像、ENV和容器；Worker桥接、Scheduler替换、API桥接切换、Admin替换各自只在选中时执行。共享变更需由清单明确列出使用方，不做自动文件依赖分析。新增SQL仍要求四角色：现有旧镜像的迁移历史校验不能接受未知新编号，本次不放宽它。配置中声明的生效使用方不得漏选；已停用的可选旧键删除可以保留未更新角色。

成功记录只增加逐角色镜像身份和本次更新角色，允许健康的混合镜像版本；全局SHA不再用于推断所有角色镜像。旧的全角色同镜像成功记录直接映射为四份相同身份，不重写历史记录。同SHA重跑验证各角色自己的镜像ID、完整有效ENV及健康，拒绝漂移、缺失、额外参数和半更新。失败不会覆盖最后成功记录，也不自动恢复旧代码。
