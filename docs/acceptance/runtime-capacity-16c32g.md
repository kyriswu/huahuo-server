[预设JSON](../../resources/runtime-configuration/16c-32g.json)记录目标值供核对，不在应用启动时导入/覆盖数据库；不更改所有部署的通用默认值。它是16核32GiB部署的起始策略，没有将本机开发容器的2核/1GiB Worker限额提升到该规格，也没有把本地回归当作该硬件的吞吐实测。

## 请求大小接线

原客户端硬编码总文件略低于100MiB，后台原有源文件200MiB无法全部送达。本轮改为显式传入客户端总文件字节预算：正式链路使用当前运行快照的storage.maxSourceBytes；试用使用其原32MiB及业务限额的较小值。预算超限在提交意图和HTTP请求前拒绝。批量文件合计受同一预算限制，未放宽16文件上限。

提供适用于现有CPU服务的[HTTP限额片段](../../resources/document-extraction/http-limits-200m.env.example)，并同步现有GPU部署模板：字段200MiB、总请求201MiB。仅调整HTTP限额，不带GPU/CUDA或OCR参数，不要求更换现有镜像。**远端机器尚未更新或开机；内网部署时应用该片段并重建现有解析容器后，200MiB才具备端到端接收条件。**
