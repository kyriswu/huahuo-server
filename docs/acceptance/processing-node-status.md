# 解析节点：云控制、内网API与发布清单（2026-11-15）

按用户最终澄清实现两项独立能力：任何能访问阿里云控制API的部署均可授权开机；解析API保持私网地址，由同VPC的Admin/Worker调用。这里指后端服务器网络，不按浏览器所在网络判定。节点清单只允许随代码发布新增，后台仅编辑已有节点。

## 最终行为

- PROCESSING_NODES_ENABLED只控制私网解析调用，默认false。独立的PROCESSING_NODES_CLOUD_CONTROL_ENABLED负责开机与空闲停机；省略/空值时，已配置完整RAM凭据或已启用节点调用则允许云控制，可显式false拒绝。会话、超级管理员、Origin/CSRF、RAM权限、机器锁和不可变快照继续保留。
- 手动开机使用维护队列、短步骤与既有Redis/PG事件，观测到实例Running即完成，不等待内网health，不因外网不可达误判开机失败，不要求私网API Bearer变量，也不回退申请新ECI。文档任务仍等待健康，并受私网调用开关约束。
- 实例状态与API连通性分开：Running即实例在线；API另显示ready/unreachable/not_checked/not_running。关闭私网调用时不探测，serviceReady为null；API不可达不把已运行实例显示成停机。常驻HTTP服务没有可查询的云电源状态，按可检测服务状态显示。
- 主表单去掉在线切换开关，原config.enabled在高级设置表示接收新任务。按需启停/常驻运行胶囊由已保存mode生成；不推断付费方式，不新增存储字段。没有手动关机按钮，运行中/启动中/未知时禁止重复开机。
- 手动开机且未参与自动调度也要遵守idleSeconds：从开机任务完成或最后一个请求结算后计时，无排队/执行/未知请求才自动节省停机。状态查看和健康检查不算业务请求，不延长计时；常驻运行节点不执行云停机。
- 状态读取只读；Redis机器事件、PG启动事件唤醒SSE，并发读取短缓存合并。没有前端状态轮询；刷新/聚焦重新核对。历史启动成功不能代表当前在线。
- 后台移除新增按钮和新建表单；服务层移除INSERT/upsert，仅更新已存在行。未知节点ID返回404、节点数量不变，已有编辑继续受版本和排空检查保护。未来新增使用已审后续编号迁移，不改冻结0001或启动时覆盖数据库。

[外网控制片段](../../resources/processing-nodes/external-control.env.example)允许云控制并关闭私网调用，控制专用Worker只消费maintenance；[同VPC片段](../../resources/processing-nodes/test-control.env.example)两项均启用。片段合入原环境，不改写既有连接和凭据。Admin文档试用继续纯内存、零入库，其PDF/Office调用同样受私网调用开关约束。
