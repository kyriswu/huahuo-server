# 应用排空与退出契约

本文件描述四个应用角色的进程行为、配置兼容和验收条件。API、Admin、Worker、Scheduler 和一次性 migrate 保持独立角色；应用入口鉴权约定见 [gateway-auth.md](gateway-auth.md)。域名入口、宿主机 Nginx 和证书仍由宿主机独立管理，本文件不配置或编排它们。实际发布流程与预算以 [standard-release.md](standard-release.md) 为准。

## 信号与状态

| 输入 | 应用行为 | 健康状态 |
| --- | --- | --- |
| 正常运行 | 接受本角色工作 | ready 同时检查依赖、基线、运行配置及后台循环 |
| `SIGUSR2` | 进入不可逆 draining；API/Admin 继续处理仍被路由过来的请求；Worker 暂停本实例消费；Scheduler 停止新扫描并关闭节点监控 | ready 503，live 200 |
| `SIGTERM` / `SIGINT` | 执行关闭，保留 API 活动 HTTP 与状态流直到完成；Admin 立即结束临时状态流；等待本地工作后释放依赖 | HTTP 监听进入关闭，不再承诺健康接口可访问 |
| 退出截止时间到达 | 仍未退出则记录 `DRAIN_DEADLINE_EXCEEDED` 并退出 `124` | 到期强制退出，须单独记录，不能声称工作自然完成 |

`SIGUSR2` 只改变应用就绪状态及后台领取行为，不会自动改变外部路由。对 API/Admin，最终退出的前提是外部入口已经停止向该实例分配新请求。Docker 的 healthy/unhealthy 标志本身不保证这一点。重复 drain 幂等；当前不提供恢复接流量的信号，回退应启动经过兼容检查的实例。

Worker 暂停只影响本进程，不暂停整个共享队列。已开始的处理保留 BullMQ 锁与 PostgreSQL 租约续期；关闭等待这些本地步骤完成。极少数暂停时已经取出、尚未领取 PG 任务的投递可由既有 Outbox 对账补投。远端等待任务以持久状态交接，不要求所有业务任务终态后才能关闭。

当前采用共享队列的轻量发布顺序：先使新 Worker 就绪，再暂停全部旧 Worker 领取；随后更新 Scheduler，最后交接 API。API、Worker、Scheduler 同机成组部署不增加任务归属组，也不要求同一时刻停止整组。旧 API 在过渡期继续受理的任务仍可由新 Worker 执行；新任务类型只能在共享队列所有旧消费者均已停止领取后产生。详细应用契约见 [部署约定](role-deployment.md#worker-优先的应用交接顺序)。

用户侧稳定性为最高优先级。Admin 文档试跑直接调用可访问的解析 API，只在内存保留状态/结果；不创建任务、审计、节点分配和持久回调记录，不接入机器开停、调度或恢复流程。允许发布/重启时中断，关闭时终止本地等待，不要求等所有试跑结束才能发布。管理员鉴权/配置读取、配置写入校验以及用户正式任务的节点占用/资源回收机制继续保留。

## 时间预算

| 角色 | 应用排空预算 | Compose 停止保护上限 |
| --- | --- | --- |
| API / Admin / Worker / Scheduler | 数据库 `deployment.drainTimeoutMs`；默认 `600000 ms`，范围 `600000–3600000 ms`（10–60 分钟） | `3630 s` |

四个角色统一从数据库运行配置读取排空预算，不再使用旧 `SHUTDOWN_TIMEOUT_MS` 或各角色的退出预算 ENV。首次 `SIGUSR2` 或 `SIGTERM` / `SIGINT` 开始计时并固定本次预算；读取配置所花时间也包含在内，后续信号和配置更新不重置期限。读取失败或超时使用最近有效快照，没有快照时使用默认值。配置读取有 1 秒等待上限；数据库配置无效时使用默认值。Compose 的 `3630 s` 只保护最大预算，不能解释为每次固定等待一小时。

工作及关闭钩子完成后立即退出 `0`；达到期限仍未完成则退出 `124`；关闭过程本身失败则退出 `1`。发布调用方须核对实际经过时间，记录 `forcedRetirements`，其他验收通过时以 `OK_WITH_FORCED_DRAIN` 区别于自然排空成功。不能仅凭退出码把提前异常退出归为正常到期。

排空预算限制进程交接等待，不限制持久任务的业务总时长。`HTTP_REQUEST_TIMEOUT_MS` 限制接收请求的时间，并非整个处理函数的截止时间。长上传、供应商调用及多步骤处理应按实际最长本地步骤评估。进程关闭完成后明确退出，避免遗留句柄让它永久驻留。整条发布链路能否容纳所选预算还需在写库前核对，详见 [标准发布预算](standard-release.md#排空预算与退出结果)。

## 排空观测

- `application_draining`：进入排空/关闭后为 1。
- `http_requests_in_flight`：尚未关闭的业务 HTTP 响应，含流，排除健康和指标探针；客户端中断后会归零，不能把它当作业务成功计数。
- `background_operations_in_flight`：Worker 本地处理器或 Scheduler 扫描及监控关闭过程。持久化远端等待不计入。

以上指标复用现有 registry。Admin 后台试跑不由这个后台工作指标统计，其临时结果不要求持久化，试跑完成与否不作为用户侧排空条件。正常请求关闭时保留活动响应，随后回收空闲连接。

API 的 `streamState` 状态流在 `preClose` 中保留订阅及依赖，等待自然终态或客户端断开；仍受上述同一进程排空期限约束，期限到达会中断剩余连接。Admin 状态流在 `preClose` 立即结束，临时试跑状态丢失时重新发起。切流不迁移已经建立的 SSE；期限中断后的客户端续传须由实际业务协议支持，不能根据连接数归零推定业务成功。

当前实际 `streamState` 业务使用者仍是 Admin；API 行为由真实 Fastify、回环 HTTP 和子进程信号测试验证，使用替身依赖，没有运行 Agent 或移动端聊天。这证明 API 底层排空行为，不代表 Agent 业务续传已验收。相关测试为 `tests/unit/lifecycle.test.ts` 与 `tests/unit/shutdown-budget.test.ts`。

状态 SSE 在写缓冲满时暂停读取、序列化和心跳，恢复后读取最新状态；只合并状态快照，不适用于增量聊天 token。单事件加待发送缓冲上限为 1 MiB，等待 drain 上限为 30 秒，超限断开；这不是整个进程内存上限或客户端收妥保证。主动关闭会立即销毁堵塞连接，其他连接正常结束。解析节点闲置监控首次订阅失败会清理旧对象，由既有 30 秒扫描重试；关闭后不会重新建立监听。验证范围及并行工作区检查阻塞见[专项验收](../acceptance/state-stream-idle-monitor.md)。

## 运行配置契约

运行配置读取与 Admin 写入使用同一份当前字段注册表。未知字段、旧 `$schemaVersion` 元数据、错误类型、越界值和秘密信息均拒绝；无效存储配置使 ready 返回 503，live 仍返回 200。Admin 保存只写入完整的当前已验证字段，沿用 revision CAS、事务和审计。

新增字段或修改字段语义需要协调相关角色的发布边界。候选 `0015` 仅清理单行配置中的已知退役字段和 v1 元数据；遇到其他未知键或未知版本先中止，不能静默删除。该迁移未执行前，不将本地候选当成目标已升级。

## 解析提交不确定状态

`intent` 表示已准备提交、但本地还未保存远端 jobId。没有可信结果时仍禁止盲重试 POST，不能为了自动恢复而重复调用可能计费的远端服务。

已认证持久回调只有同时匹配请求身份、内容指纹和远端 jobId 才能将相应 intent 收敛为已提交 job。按任务→回调收件箱顺序锁定，保留任务版本、租约和取消标记；原活 Worker 或原 Scheduler 恢复路径继续处理。重复回调不重复产生业务效果，冲突拒绝，旧请求不能覆盖新请求。无可信回调时仍保持待核对，不承诺所有未知提交自动恢复。

取消与已知远端任务提交并发时，同一有效租约持有者可交回执行权并立即再投递，让新 attempt 继续取消；该窄交接不允许旧 attempt 提交结果，不允许 intent、不匹配 owner/attempt 或失效租约交接。

## 尚未覆盖的发布条件

应用排空机制本身不证明发布全链路通过。入口鉴权验证范围见 [验收](../acceptance/ingress-auth.md)，实际测试服务器发布与生产接入边界见 [标准发布](standard-release.md)。上传断点续传、Scheduler 错过时间窗补跑和 Agent SSE 续传仍需各自业务证据。Admin 试跑状态持久化已明确不要求，不列入待办或验收阻塞。共享 PG/Redis/存储、密钥稳定性、版本间数据/任务兼容、重叠容量须在实际发布前验证，不能把复制整套 Compose 成两个 project 当成共享依赖的应用双实例。

测试服务器已于 2026-11-15 首次自动发布，已经执行的 `0001` 及后续迁移冻结；后续变更新增编号，不重写历史或 checksum。回退应用保留已提交迁移，不运行旧迁移器。原“未上线只维护单基线”规则已结束。

验收与证据见 [应用发布基础加固](../acceptance/release-hardening.md)。

同机真实容器分角色切换及回切的历史演练见 [容器演练](../acceptance/release-rehearsal.md)；其中旧初始化基线 checksum 阻断属于该次历史结果，不能作为当前线上发布状态。当前同机部署组与共享队列方案见 [部署契约](role-deployment.md) 及 [轻量发布验收](../acceptance/worker-first-release.md)。
