# Milvus 无正文检索

`KB_INDEX_LAYOUT=sparse-v1` 使用两个独立集合。它们在已有集合配置值后加 `_sparse_v1`。资产集合存稠密和稀疏向量，文件和独立文本集合存稀疏向量。两个集合都保留稳定点 ID、用户、工作区、来源及索引状态，关闭动态字段。正文来源是 PostgreSQL，文件的规范正文由 PostgreSQL 记录对应的对象 URI。App API 和返回结构沿用现有契约。 [资产术语与正文来源](../content-assets.md)

## 召回与回查

| 模式 | 召回路径 |
| --- | --- |
| `keyword` | 沿用 Milvus 的 Jieba、English 和 ICU 分词。语言路由进入稀疏向量坐标，一次内积召回。 |
| `dense` | 沿用 1024 维 FP16 向量和余弦距离。 |
| `hybrid` | 汇总各页的全局稠密和稀疏分支排名，用一次 RRF 融合。 |

0022 在 PostgreSQL 维护只追加的哈希词项字典，保证已有坐标在编辑、重试和换进程后稳定。词频权重使用固定参考长度，查询词使用等权。排序分数会和原生 BM25 不同。分词调用 Milvus 的分析器，正文只作为分析请求输入。索引写入只带向量和筛选字段。Server 进程内缓存有界的查询编码，未分配的坐标可在后续查询时重新读取。 [Milvus 稀疏向量](https://milvus.io/docs/v2.6.x/sparse_vector.md) · [旧版 BM25 输入要求](https://docs.zilliz.com/docs/full-text-search)

默认关闭可选外部重排。Milvus 只返回候选点 ID 和分数，Server 先查 Top K 涉及的当前构建，用一次 PostgreSQL 集合查询拿正文或对象 URI。按分块范围和哈希验证片段，失效候选按原排名用剩余候选补齐，并再核对最终返回项的权限和当前修订。同一来源在请求内只回查一次。启用外部模型时批量取重排预算内的正文，随后再截取 Top K。文件对象仍按来源读取。 [查询实现](../../src/modules/rag/query-service.ts) · [批量回查用例](../../tests/unit/rag-global-recall.test.ts)

## 编辑与清理

资产保留分块正文哈希、向量化输入哈希和重复块出现次数。新代集合独立记录构建状态，相同输入可沿用旧版点 ID。同一集合内只向量化和写入变化的分块。新构建发布后，清理旧版独有点，按构建存储的真实集合执行。隔离验收验证编辑一个章节只向量化一块，删掉一个章节时向量化零块，旧点从对应集合消失。 [索引执行](../../src/modules/kb/jobs.ts)

## 测试环境维护切换

1. 等受保护 `main` 的 Compose 透传由 owner 合入，以及业务 `test` 合入提交的 Server CI 通过。确认测试成功基准仍是 `3f751ac`。准备同一份候选配置 `KB_INDEX_LAYOUT=sparse-v1` 和 `RAG_RERANK_PROVIDER=disabled`。普通自动发布继续按清单停在不兼容门禁。
2. 用现有维护锁排空旧角色和索引任务。重新核对集合名称与 ID、PostgreSQL 已发布构建和未完成索引任务，以及开发和测试共用库的实际状态。首轮只读预检显示 0021，两套旧集合、已发布构建和待索引任务均为零，测试 Milvus 可运行 Jieba。若出现活跃旧构建，先完成按修订重建和对账。若旧集合点数变化，先核对其归属与发布状态。
3. 通过候选现有索引创建入口初始化两套新集合，验收字段白名单、向量类型与度量。以已审清单执行 0022 与各角色数据库验收，按既有门禁切换角色和恢复写入。
4. 在测试新目标用可回收夹具验证 `keyword` 和 `hybrid`。复查旧集合仍无运行配置、待处理任务或已发布构建依赖，再对照维护前记录的两个集合 ID 退役旧集合。此步骤也需走已审维护入口。 [标准维护发布](standard-release.md) · [发布验收脚本](../../scripts/release/changes/20261119-milvus-textless/)

## 验收方法

`pnpm test:integration --milvus --search-benchmark` 使用隔离的 PostgreSQL、Redis、Milvus 2.6.26 和合成 embedding。按相同标注语料、候选预算、Top K 3 和并发 4 对照旧版 BM25 布局与无正文布局。语料包含中文、英文和混输，负载扩展到 304 个资产分块。分别报告预热重复查询与未命中查询缓存的 QPS、P95 和 P99。干扰文档覆盖多个分块，稀疏索引和正文回查均走实际数据库。结果适用于相同规模的隔离对照，真实云对象读取、付费模型延时及共享环境容量需单独测量。
